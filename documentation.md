## 1. Activation Quantization: Static vs Dynamic

In **dynamic** mode, activation scales (and zero-points for asymmetric) are computed per-token at inference time: each token's activation row gets its own scale derived from its actual min/max. This gives optimal quantization but requires runtime computation. In **static** mode, scales are precomputed once during calibration (`calibrater/calibrate_act_scales.py`) by observing activations across many calibration tokens. The calibrator records per-column min/max statistics across all tokens, then derives a single (scale, zero) pair per column that covers the full observed range. These are saved to disk and loaded at inference time — no per-token computation needed.

## 2. Standard GEMM vs Integer GEMM

The critical difference between **standard GEMM** and **integer GEMM** (`--int_gemm`) is how scales interact with the dot product. In standard (float) GEMM, quantized activations are immediately dequantized back to float before the matmul, so per-column scales work fine — each column's scale multiplies independently. In integer GEMM, the multiply-accumulate happens in integer arithmetic inside hardware accumulators of limited width (`--acc_bits`). Scales cannot be applied per-column because they'd need to factor out of the integer dot product, which is impossible when each column has a different scale. Instead, static int_gemm uses **per-group** scales where one scale covers `acc_block_k` consecutive columns — exactly one accumulator block. This way the scale factors out of each block's partial sum. The per-group (scale, zero) is derived from the per-column calibration data by taking the min/max of the representable ranges within each group. For **asymmetric** quantization (non-zero zero-points), the zero-point correction is precomputed as a constant `[N]`-dimensional bias vector (`static_zp_bias`) at setup time and added after the integer kernel — no kernel modifications needed.

## 3. Tier-2 Accumulator (T2 / auto-acc-dtype)

Integer GEMM with a fixed accumulator clamps at `2^(N−1)−1`, and choosing the per-layer right-shift (`frac_bits`) ahead of time is a no-win: too conservative wastes precision, too aggressive saturates. **Tier-2** (`--acc_dtype int<N>a<Y>`, e.g. `int24a0`, `int28a0`) sidesteps the choice by *deferring* `frac_bits` until after activation calibration. It reads each layer's post-cal `out_quantizer.scale`, computes how many integer bits the output magnitude actually needs, and assigns the rest to fractional precision per layer. `Y` is reserved safety headroom above the observed MSB. The auto-resolver then rewrites every layer's `acc_dtype` to a concrete `int<N>p<M>` form at init. **Pitfall:** the resolver needs `out_quantizer.scale` populated, so calibration must NOT receive `--acc_dtype int<N>a<M>` — cal hasn't produced the scales yet, and a degenerate fallback contaminates the cal forward (see `project_acc_dtype_cal_bleed.md` in memory). Anchor: `fake_quant/int_acc_gemm.py:86` (`resolve_auto_acc_dtype`).

## 4. Hardware Scale Encoding (hwscale)

Deployable hardware can't store arbitrary FP32 scales — it stores a small mantissa and a small shift. `--hwscale <spec>` snaps merged activation/weight scales to the form `mantissa × 2^(−shift)` so fake-quant inference matches the hardware's representable-scale grid. The spec format is `M<m>S<s>{bias}`: `m` mantissa bits, `s` shift bits, and a bias suffix that picks the per-layer global exponent. The bias modes differ in how they anchor the layer's exponent: `bmin` anchors at the smallest representable value (giving headroom below the smallest observed scale), `bmid` centers on the median in log-space, `bopt` does an MSE-optimal brute-force search over `z±4`, `best` extends to non-power-of-2 globals (`m_frac × 2^(−z)`), and explicit `bz<N>` / `lz<N>` fix the global exponent. Anchor: `fake_quant/quant_utils.py:99` (`hwscale_global_from_spec`); supporting `parse_gscaler` (line 17) and `snap_scale_to_gscaler` (line 64).

## 5. Scalewise GPTQ

The naive flow with hwscale is: GPTQ rounds weights against FP scales, then post-hoc snaps the scales to the M\<m\>S\<s\> grid. The post-hoc snap reintroduces error that GPTQ already compensated against — wasted work. **Scalewise** (`--scalewise`, requires `--hwscale` and `--fp16_calib`) folds the scale-snap *inside* the Hessian-weighted GPTQ loop: each per-group scale is pre-rounded to its M\<m\>S\<s\> representation as part of the per-group quantization step, so Hessian compensation absorbs both weight-rounding and scale-snapping error simultaneously. This closes the accuracy gap that coarse `M4S4` scales were leaving on the table. Anchor: `fake_quant/quant_utils.py:1420` (`WeightQuantizer.init_scalewise`); GPTQ integration in `fake_quant/gptq_utils.py`.

## 6. GPTAQ

Standard GPTQ minimizes `||W·X_Q − W'·X_Q||²` — both sides see the *quantized* activation trajectory. But at inference, the activations entering layer 0 are FP and only get progressively quantized further down the stack. **GPTAQ** (`--gptaq`, requires `--fp16_calib`) shifts the loss to `||W·X_FP − W'·X_Q||²`: match the FP-trajectory output using the Q-trajectory input. The closed-form minimizer is `W' = W + W(C − H)H^(−1)`, where `H = X_Q X_Q^T` is the Hessian GPTQ already collects and `C = X_FP X_Q^T` is a new cross-correlation statistic accumulated by running a parallel FP forward at calibration time. The per-block flow snapshots FP weights before quantization, runs paired FP + Q forwards in lockstep, accumulates `H` and `C` together, then *pre-shifts* `W → W + δ` before the existing Cholesky loop. The pre-shift compensates for the FP→Q activation gap upfront, freeing Hessian compensation to focus on weight rounding. Checkpoints live in `data/gptaq_checkpoints/` (separate from `data/gptq_checkpoints/`) to avoid collision when sharing the same config. Anchor: `fake_quant/gptaq_utils.py:41` (`gptaq_fwrd`).

## 7. FP4 Weight Quantization

True FP4 (E2M1-like) has unevenly-spaced levels: small magnitudes get more codes, large magnitudes fewer. This compresses well for weights with heavy-tailed distributions where most mass is small but rare outliers still need range. **FP4** (`--fp4 {all | down | none}`) uses a 16-level symmetric code set `{0, ±1, ±2, ±3, ±4, ±6, ±8, ±12}` scaled by `amax / 12`. `--fp4 all` applies to every weight projection; `--fp4 down` restricts to `down_proj` only. The dequantization path uses `bucketize` on midpoints for exact nearest-neighbour mapping. GPTQ Hessian compensation and scalewise rounding both work unchanged because the snapping primitive is just "find nearest code in this 16-element set" — drop-in compatible with the rest of the pipeline. Anchor: `fake_quant/quant_utils.py:341` (`fp4_quant_dequant`); code table at `_FP4_CODES` (line 334).

## 8. Piecewise-Linear Activations (PWL)

Hailo APUs can't evaluate SiLU or GELU directly — they evaluate piecewise-affine functions. **PWL** (`--pwl_act`) replaces the non-linear activation with an N-segment approximation: `N−1` thresholds split the input range, and each segment carries its own (slope, offset) pair. To match the hardware's precision the slopes are stored in mantissa+exponent form (default 10-bit mantissa, 4-bit exponent) and the offsets in fixed-point (default 13 bits), all simulated at fake-quant time so accuracy on this codebase predicts deployed accuracy. Default coefficients for SiLU and GELU are hardcoded from the Hailo SDK reference; the `pwlf` library is available for re-fitting non-standard activations. Interaction with quantization: with `--ugd_eq`, the per-channel scale rides on the PWL output (HW-accurate); without it, an `EqActivation` wrapper applies the scale in fake-quant. Anchor: `fake_quant/pwl_utils.py:28` (`PWLCoefficients`); coefficient tables `SILU_PWL` (line 58) and `GELU_PWL` (line 73).

## 9. GGUF Loading

llama.cpp's pre-quantized weights (Q4_K_M, Q4_K_S, Q5_K, Q6_K, Q8_K, etc.) are well-studied baselines, so being able to load them into our HF pipeline lets us compare our GPTQ output against llama.cpp's quantization on the same architecture. **GGUF loading** (`--gguf <scheme|path>`) dequantizes weights to float at load time and replaces HF model weights in place; `--imitate_gguf <scheme|path>` matches only the per-layer bit-widths from a GGUF file (no actual weight load — useful when comparing schemes). **Critical detail:** llama.cpp's `convert.py` interleaves Q and K rows by head-halves to make RoPE more cache-friendly. If you skip the reverse permute on load, Q/K weights are scrambled and PPL goes from ~18 to ~1600 — the kind of bug that takes hours to track down without knowing it's a known artifact of the format. Anchor: `fake_quant/gguf_utils.py:70` (`_reverse_permute`); type table `GGUF_TYPE_SPECS` (line 41); entry point `load_gguf_weights` (line 173).
